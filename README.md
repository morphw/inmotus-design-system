# InsaOS Design System

Переносимый визуальный язык и приёмы интерфейса приложения InsaOS. Репозиторий содержит готовые CSS-токены, необязательные стили базовых компонентов, каталог интерфейсных приёмов, живой предпросмотр и Codex Skill. Функции исходного приложения сюда не входят.

## Что можно выбрать отдельно

| Слой | Файлы | Когда брать |
| --- | --- | --- |
| Визуальный стиль | [`tokens/insaos.css`](tokens/insaos.css) | Нужны цвета, шрифт, размеры, скругления и тени InsaOS |
| Базовые компоненты | [`components/insaos.css`](components/insaos.css) | Нужны кнопки, карточки, поля и демонстрационные элементы без UI-библиотеки |
| Приёмы интерфейса | [`patterns/interface.md`](patterns/interface.md) | Нужны навигация, адаптивные панели и характер движения, возможно с другой темой |
| Инструкция для Codex | [`SKILL.md`](SKILL.md) | Хочется применять выбранные слои по запросу в других проектах |

Каждый слой можно пропустить. CSS-классы и переменные имеют префикс `insa`, поэтому их можно подключать постепенно. React, Tailwind, Radix, Motion и другие библиотеки исходного проекта **не требуются**.

## Как использовать в новом проекте

### Вариант 1: отправить ссылку Codex

В новом чате можно написать:

> Используй дизайн-систему https://github.com/morphw/insaos-design-system версии v0.1.0. Возьми визуальный стиль и мобильную навигацию, но оставь текущие библиотеки проекта. Не добавляй функции InsaOS. Сначала посмотри репозиторий и существующую структуру моего проекта.

Если репозиторий приватный, среде Codex нужен доступ к GitHub или локальная копия. Одна ссылка сама по себе доступ не выдаёт. Вместо ссылки можно указать путь к локальной копии или приложить архив.

### Вариант 2: подключить файлы к проекту

Скопируй `tokens/insaos.css` в проект и импортируй его. Оберни нужную часть интерфейса в элемент с классом `insaos-theme`:

```html
<div class="insaos-theme" data-insaos-theme="light">
  <!-- приложение -->
</div>
```

Для тёмной темы поставь `data-insaos-theme="dark"`. При необходимости подключи `components/insaos.css` после токенов. Пример: [`preview/index.html`](preview/index.html). Токены имеют значения внутри `.insaos-theme`, поэтому они не оформляют остальные части страницы.

Можно хранить репозиторий как Git submodule, отдельный пакет или просто копировать выбранные файлы. Для одного проекта удобнее начать с копирования; для нескольких проектов, которые регулярно получают обновления, подходит submodule или пакет.

### Вариант 3: подключить Skill

Папка этого репозитория одновременно является Codex Skill: в корне лежит `SKILL.md`. Чтобы Skill был доступен в разных задачах на одном компьютере, помести **всю папку** репозитория в каталог личных навыков Codex (`~/.codex/skills/insaos-design-system`) или создай на неё ссылку. Если работаешь только в одном проекте, можно держать папку в проектном каталоге навыков. После этого попроси: «Используй `$insaos-design-system`, но только приёмы интерфейса; тему и библиотеки оставь текущие».

Skill читает файлы этого репозитория. Он не должен молча заменять выбранные проектом библиотеки или оформление.

## Версии и обновление

- Релиз `v0.1.0` фиксирует исходный визуальный язык по состоянию приложения на 24 сентября 2026 года.
- Новые проекты могут выбрать актуальный релиз, а существующие — оставаться на закреплённой версии.
- Меняй `tokens/insaos.css` как источник значений. После изменения цветов запускай `node scripts/export-tokens.mjs`; он обновит совместимый JSON-экспорт `tokens/insaos.tokens.json`.
- Перед обновлением проекта сравни выбранную версию с новой и перенеси только нужные слои. Изменения в этом репозитории сами по себе не меняют другие приложения.

## Происхождение и границы

Набор извлечён из InsaOS (`morphw/InsaOS`, коммит `9704db8`). Светлая и тёмная палитры, скругления, тени и длительности движения взяты из `apps/frontend/src/index.css`, `apps/frontend/tailwind.config.ts` и `apps/frontend/src/core/motion/motion.tokens.ts`. Компоненты и приёмы описаны по общим UI-компонентам и оболочкам мобильного и десктопного интерфейса. Это самостоятельный набор без бэкенда, календаря, персональных данных, логотипа и прикладных модулей.

Открой [`preview/index.html`](preview/index.html), чтобы увидеть оба режима и базовые элементы без сборки и зависимостей.
